## Summary of material findings

Ordered by effect on the brief's recommendations. All are inputs for the writers; none closes an open question.
Legal readings are interpretations, not legal advice.

1. **Q4 sign-in vs WCAG 3.3.8 (new design constraint).** The 6-digit email code passes SC 3.3.8 only if
   the code field accepts pasting the whole code in the same format and autofill is not blocked. A split
   six-box input that fills one digit on paste is the page's own failure example (F109). Put this in ADR
   0004 and the S1 sign-in screen checklist.
   https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html
2. **shadcn "base can't change after init" is overstated (brief §3, design row).** `style` can't be
   changed after init (confirmed), but shadcn documents a progressive Radix-to-Base UI migration (via an
   AI-agent skill, component by component). No documented path exists to or from React Aria. Reword to
   "costly to change later", and keep the spike before choosing. The migration route uses a coding agent,
   which touches PQ-16. New projects now default to Base UI, so scaffolding must pass `--base aria`
   explicitly if React Aria is chosen.
3. **Node version floor is wrong in T1.** The engines intersection of Vitest 5.0.3, dependency-cruiser
   18.6.0 and ESLint 10.12.0 is **Node 22.13+ on the 22 line, any 24.x, or >= 26**. Node 23 and 25 are
   excluded, and 22.12 is too low for ESLint 10. Pin one Node line in CI, locally and on the host.
4. **AODA / Policy 58 legal floor is uncertain in both directions (Q15, PQ-51, PQ-60).** Kept from the
   first pass and extended. The Ontario WCAG 2.0 AA duty covers *public* websites, not intranets or
   extranets, and falls on the organization that controls the site. Colleges and universities are
   designated public sector organizations (official answer to PQ-60's first half). UW's own accessibility
   pages name no WCAG version. The WCAG 2.2 AA proposal still meets every floor found, except that
   2.0-based policies may still expect 4.1.1 Parsing to be tested and reported.
5. **WCAG 2.2 date (D1).** It became a Recommendation on 5 Oct 2023; 12 Dec 2024 is the current
   updated version. The SC numbers and levels in D1 Appendix C are now verified (2.3.3, 2.4.12, 2.4.13 and
   1.4.6 are AAA, i.e. stretch goals only).
6. **Small-cell sources (Q16, PQ-36).** All three are confirmed as quoted. Scope caveats belong in the
   final doc: TBS PIN 2020-03 binds federal institutions only, and PTAC is US/FERPA guidance ("Oct 2012,
   updated May 2013"). The IPC guideline (Low 0.1 = 10, Medium 0.075 = 15, High 0.05 = 20, "illustrative
   only") is the closest fit, because it is written for Ontario FIPPA institutions and UW operates under
   FIPPA. N = 10 stays a placeholder; "refuse below 3" is supported by both TBS and PTAC.
7. **CI artefact and log retention (PQ-70, PQ-14).** GitHub keeps workflow artifacts *and logs* for 90 days
   by default (private repos 1–400 days, public 1–90). Canary-scanner output and Playwright traces persist
   for that long unless the period is shortened or set per artifact. The 500 MB Free artifact quota can't
   be raised by Support.
8. **pgTAP is not in the stock `postgres:18` image.** It needs `postgresql-18-pgtap` (1.3.4) or a custom
   image, which costs CI minutes. The brief already makes pgTAP optional. Plain SQL catalogue assertions
   avoid the cost. Supabase's documented `supabase test db` path starts the full Supabase stack, which
   doesn't match "Supabase as plain Postgres".
9. **Mutation testing is not CI-ready on Vitest 5 (PQ-69).** The Stryker vitest-runner 10.0.0 was published
   2026-08-14, before Vitest 5.0.0 (2026-09-03). "Works with Vitest 5" stays Unverified, so a spike is
   needed. Stryker's default `thresholds.break` is `null`: it never fails CI unless the owner sets a
   threshold. The 80/60 defaults only set report colours and are not project thresholds.
10. **Lint stack conflict.** eslint-plugin-jsx-a11y 6.10.2 (last published 2024-10-26) has a peer range
    that stops at ESLint 9, and the ESLint 10 support issue (#1075) and PRs are still open. With ESLint 10,
    use Biome's 37-rule a11y group, or stay on ESLint 9. This doesn't affect the axe/Playwright gate.
11. **Licences and trademarks.** shadcn (MIT), Tailwind (MIT), Base UI (MIT), React Aria (Apache-2.0), axe-core and
    @axe-core/playwright (MPL-2.0), the fonts (OFL-1.1, including Atkinson Hyperlegible Next via
    google/fonts) are all confirmed. Apache-2.0 s. 6 grants no trademark rights. D2L forbids its marks in
    product, app or domain names and any implied affiliation, and gives no referential-use permission
    (PQ-59). UW logo exceptions are given only in writing and "for official business" (PQ-07).
12. **Stale versions (not decision-relevant).** govuk-frontend latest is 6.5.1 (2026-09-14, not 6.5.0).
    eslint-plugin-boundaries latest is 7.2.0 (its docs still show 7.1.0). Playwright 1.64.0 was published
    2026-10-07. dependency-cruiser 18.6.0 was published the day of the check, so pin it.
13. **Citation fixes.** T1's "automated testing can't catch all issues" should cite the Playwright page,
    not axe API.md. The 41% in the GDS 2017 study counts manual-inspection prompts; on errors and warnings
    alone the best tool found 37%, and aXe (before 3.0) found 29%. The status-message alert-overuse failure
    has no failure ID yet. The GOV.UK typography URL is a 404: use `/styles/typeface/`.

render); the CRTC CASL FAQ (403); whether every shadcn component has a React Aria variant; Stryker on
Vitest 5; a UW IST vendor rule requiring a newer WCAG version; whether third parties may use the UW logo;

behaviour.
